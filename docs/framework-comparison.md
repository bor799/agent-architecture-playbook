# Agent 框架对比参考指南

> 用于教学过程中的框架对比参考

---

## 主流框架概览

| 框架 | 核心特点 | 适用场景 | 复杂度 |
|-----|----------|----------|--------|
| LangChain | 生态最丰富，组件齐全 | 快速原型、企业级应用 | 高 |
| CrewAI | 多 Agent 协作 | 并行任务、角色分工 | 中高 |
| AutoGen | 多 Agent 对话 | 复杂推理、辩论式决策 | 高 |
| Netbo | 单层循环，极简 | 轻量级单 Agent 应用 | 低 |
| LlamaIndex | 数据索引优先 | RAG、知识库应用 | 中 |

---

## 核心架构对比

### 消息机制

| 框架 | 消息处理 | 循环机制 | 用户控制 |
|-----|----------|----------|----------|
| Netbo | 单层循环 | 固定 N 轮 | 无内置支持 |
| LangChain | 双层消息 | 可配置 | 支持中间干预 |
| CrewAI | 任务队列 | 任务驱动 | 有限支持 |

**选择标准**：
- 需要用户实时干预 → LangChain / 自建双层循环
- 单次执行即可 → Netbo / 简单封装

---

### 工具体系

| 框架 | 工具定义 | 工具执行 | 安全机制 |
|-----|----------|----------|----------|
| LangChain | 装饰器/类 | 并行执行 | 内置权限层 |
| Netbo | 函数注册 | 串行为主 | 简单白名单 |
| OpenAI | JSON Schema | 并行执行 | 依赖模型 |

**选择标准**：
- 复杂工具生态 → LangChain
- 简单工具集 → Netbo / 自建
- 需要 MCP → 选择支持 MCP 的框架

---

### 记忆系统

| 框架 | 短期记忆 | 长期记忆 | 向量搜索 |
|-----|----------|----------|----------|
| LangChain | 缓存 | 多种后端 | 集成支持 |
| CrewAI | 共享上下文 | 有限 | 需自建 |
| Netbo | 会话级 | 需自建 | 需自建 |

**选择标准**：
- 需要长期记忆 → LangChain / 自建
- 只需会话级 → 任意框架

---

## 选型决策树

```
开始
  │
  ├─ 需要用户实时干预？
  │   ├─ YES → 考虑双层循环框架
  │   └─ NO → 可选择单层框架
  │
  ├─ 工具有副作用比例？
  │   ├─ 高（>50%）→ 需要强控制机制
  │   └─ 低（<30%）→ 简单框架即可
  │
  ├─ 需要长期记忆？
  │   ├─ YES → LangChain / 自建
  │   └─ NO → 轻量框架
  │
  └─ 团队背景？
      ├─ 工程强 → 可自建
      └─ 产品驱动 → 选现成 SaaS
```

## 常见误区

### 误区 1：多 Agent 一定优于单 Agent

**纠正**：多 Agent 增加复杂度和成本。单 Agent + 工具足够解决 80% 场景。

### 误区 2：需要所有功能

**纠正**：按四阶模型判断需求。过早引入第四阶能力是过度工程。

### 误区 3：双层循环 = 双层消息

**纠正**：这是两个独立设计。双层循环控制行为，双层消息管理数据。

## 快速对比检查表

在分析新框架时，回答以下问题：

- [ ] 属于四阶模型的第几阶？
- [ ] 是否支持双层循环？（用户可干预）
- [ ] 是否使用双层消息？（UI/LLM 分离）
- [ ] 工具执行是串行还是并行？
- [ ] 如何处理有副作用的工具？
- [ ] 记忆机制的实现方式？
- [ ] 是否支持 MCP？
- [ ] 学习曲线和上手难度？
