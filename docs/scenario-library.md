# Agent 框架业务场景库

> 用具体产品场景解释抽象的架构概念

---

## 四阶模型场景示例

### 第一阶：大脑（LLM API）

**场景**：一次性问答

> "帮我总结这篇文章"
> "这个 Python 代码是什么意思？"

**特点**：
- 用户输入 → LLM 处理 → 返回结果
- 无状态，不记得之前说过什么
- 无工具调用能力

**产品示例**：ChatGPT 单次对话、翻译 API

---

### 第二阶：手脚（工具体系）

**场景**：单次任务执行

> "帮我把这个文件转换成 PDF"
> "搜索最新新闻并发邮件给我"

**特点**：
- 能调用工具完成任务
- 做完就忘，下次对话从头开始
- 无法自我纠错或探索

**产品示例**：单次任务 Agent、批量处理脚本

---

### 第三阶：经验+自主性（记忆 + 循环）

**场景**：多轮对话 Agent

> "帮我分析这个竞品...（等待结果）...再深入看看他们的定价策略...（等待）...总结一下差异"

**特点**：
- 能记住之前的对话
- 能根据结果自主决定下一步
- 可进行多轮探索

**产品示例**：Claude Code、代码审查 Agent

---

### 第四阶：协作能力（用户实时控制）

**场景**：协作式 AI 助手

> 用户：帮我把这个函数重构成...
>
> AI：开始重构...
>
> 用户：等一下！先别改那部分，先处理...
>
> AI：好的，跳过那部分，继续...

**特点**：
- 用户能观察执行过程
- 用户能中途打断
- 用户能追加新需求
- 用户能纠正方向

**产品示例**：Cursor、协作式编程助手

---

## 双层循环 vs 双层消息场景

### 双层循环场景

**需要双层循环**：
- 协作式编程助手（用户可能中途改变主意）
- 数据分析 Agent（用户可能想调整分析方向）
- 自动化交易 Agent（用户需要紧急停止）

**不需要双层循环**：
- 批量文件处理（跑完就行）
- 自动化报告生成（无需中途干预）
- 后台数据同步（无人值守）

---

### 双层消息场景

**需要双层消息**：
- 需要显示给用户但不需要 LLM 知道的信息（如 UI 状态、进度条）
- 需要存储但不想消耗 token 的元数据（如时间戳、用户 ID）

**不需要双层消息**：
- 简单的对话历史
- 不需要 UI 的后台任务

---

## 工具副作用场景

### 高副作用场景（需要强控制）

**场景**：自动化运维 Agent

工具列表：
- `restart_service()` - 重启服务（有副作用）
- `delete_logs()` - 删除日志（有副作用）
- `send_alert()` - 发送告警（有副作用）
- `check_status()` - 检查状态（无副作用）

**影响**：100% 有副作用工具
**结论**：必须支持双层循环，用户需要能随时打断

---

### 低副作用场景（简单框架即可）

**场景**：内容分析 Agent

工具列表：
- `read_file()` - 读取文件（无副作用）
- `search_web()` - 网络搜索（无副作用）
- `analyze()` - 分析内容（无副作用）
- `save_report()` - 保存报告（有副作用，仅1个）

**影响**：25% 有副作用工具
**结论**：单层循环框架足够，最后一步人工确认即可

## 框架选型场景

### 场景 1：企业内部知识库问答

**需求分析**：
- 用户提问 → 搜索知识库 → 返回答案
- 需要长期记忆（用户历史）
- 无需用户干预
- 工具副作用低（只读）

**推荐**：
- 第二阶 + 简单框架
- LangChain（已有向量集成）或自建

---

### 场景 2：自动化代码审查机器人

**需求分析**：
- 监控 PR → 分析代码 → 自动评论
- 无需用户实时干预
- 工具有副作用（发评论）
- 需要记忆（已审查的 PR）

**推荐**：
- 第三阶 + 中等复杂度框架
- 自建或轻量框架

---

### 场景 3：协作式编程助手

**需求分析**：
- 用户和 AI 共同工作
- 需要实时干预
- 工具副作用高（修改代码）
- 需要短期记忆

**推荐**：
- 第四阶 + 双层循环框架
- 需要精心设计或使用成熟框架

## 概念类比库

### Agent = 员工

| 概念 | 类比 |
|-----|------|
| LLM | 大脑 |
| 工具 | 手脚 |
| 记忆 | 笔记本 |
| 双层循环 | 主管随时打断 |
| 双层消息 | 工作日志（给主管看的 vs 给自己看的） |
| MCP | 外包服务 |

---

### 工具执行 = 任务分配

| 类型 | 场景 |
|-----|------|
| 读取类工具 | 查资料、看文件 |
| 写入类工具 | 写文档、发邮件 |
| 通信类工具 | 打电话、发消息 |
| 有副作用 | 不可逆操作（删除、发布） |

## 练习场景

### 练习 1：电商客服 Agent

一个处理客户咨询的 Agent：
- 回答常见问题（知识库）
- 查询订单状态（API 调用）
- 处理退款（有副作用）
- 需要人工审核某些情况

**问题**：
1. 这个产品属于第几阶？
2. 需要双层循环吗？
3. 工具副作用比例如何？
4. 用什么框架合适？

---

### 练习 2：自动化测试生成器

一个自动生成测试代码的 Agent：
- 读取源代码
- 分析测试覆盖
- 生成测试文件（有副作用）
- 运行测试（有副作用）

**问题**：
1. 需要用户干预吗？
2. 什么情况下需要双层循环？
3. 如果测试失败，Agent 应该能做什么？
